Choix techniques

Quatre choix qui guident le projet

PHP natif, sans framework

PHP et PDO côté serveur, HTML et CSS écrits à la main côté navigateur. Seule bibliothèque : Chart.js

Les règles dans la base

Des déclencheurs refusent les erreurs et tiennent le stock à jour, des tâches programmées gèrent les quais

La sécurité

Mots de passe hachés, requêtes préparées, chaque profil n’accède qu’à ses pages

Des données réalistes

Environ 120 000 lignes générées en SQL, qui passent par les mêmes déclencheurs que le site

[Orateur 3] Nos choix techniques. Un : pas de framework. Côté serveur, le site est en PHP natif, avec PDO pour parler à MariaDB ; ce sont les outils vus en cours, et chaque requête SQL est écrite à la main, donc visible et explicable. Côté navigateur, ni Bootstrap ni React : du HTML et une feuille de style écrite par nous. La seule bibliothèque externe est Chart.js, pour les graphiques des indicateurs. Deux : nous avons mis les règles importantes directement dans la base, avec des déclencheurs : même une requête SQL tapée à la main ne peut pas les contourner. Mon collègue les détaille à la diapo suivante. Trois : la sécurité, avec des mots de passe hachés, des requêtes préparées contre l’injection SQL, et des pages réservées à chaque profil. Quatre : des données de test réalistes, environ 120 000 lignes générées en SQL ; elles passent par les mêmes déclencheurs que le site, donc elles respectent toutes les règles. (≈ 40 s)
